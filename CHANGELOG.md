## 1.0.0-beta.1 – 2026-10-09

Proof, not features: the items the fourth review of v1.0.0-alpha.2
still listed as open, minus the independent audit that no commit can provide.
The alpha label had become more conservative than the code; beta.1 says so.

### security-audit
- **`AUDIT_ANCHOR_STORES=` (empty) no longer means "no anchors".** An empty or whitespace-only list now falls back to `['database']`; previously the config parsed it into an empty list, the composite store became a `NullAnchorStore`, and outside production (where the guard would have refused) anchors were silently dropped. Found while extracting the configuration reference.
- **The append-only switch reads like every other boolean.** The migration parsed `audit.enforce_append_only` with `(bool)`, so `AUDIT_ENFORCE_APPEND_ONLY=false` — a non-empty string — still installed the triggers (harmless) while `0` did not; it now uses `filter_var(FILTER_VALIDATE_BOOL)` like the guard and the doctor, and the reference documents the accepted spellings.
- **`security:doctor --json` honours `--strict`.** `healthy` was `true` for a report with warnings even under `--strict`, although the exit code was 1; the JSON now carries `healthy` (false on any failure and, under `--strict`, on any warning) and `strict`, so a pipeline can gate on the JSON alone.
- **Known-answer vectors for the hash format.** `packages/audit/tests/Fixtures/hash-vectors.json` records two complete events (genesis on a tenant chain with nested, unsorted, non-ASCII metadata; a chained system event on the global chain with empty metadata) with their canonical JSON, SHA-256 event hash and HMAC-SHA256 signature under a fixed key, and `HashVectorsTest` pins them together with `HashableRecord::VERSION`, the domain string (byte for byte), the exact set of hashed fields and the HMAC construction. Until now every hashing test compared hashes with each other, so the mutation report showed changes to the version, the `v` field and the domain separation surviving; now any such change is a failing test, i.e. a deliberate new hash version. The vectors are computable without this code base (`sha256(domain ‖ canonical_json)`). (Constant declarations still show as "uncovered" in the mutation report — pcov cannot attribute a test to a line without executable code — but a bumped `VERSION` or a changed JSON flag now fails the suite, which is what matters.)
- **`security:doctor --strict` is the deployment gate of the high-security profile.** Besides treating warnings as failures it now fails the `anchor_stores` check unless `AUDIT_REQUIRE_EXTERNAL_ANCHOR=true` is set: an external store that is merely configured is not enough, because nothing would stop a later deployment from dropping it; the requirement has to be enforced by the boot guard. The default stays opt-in (a library must install and run without an object-locked bucket), but a pipeline that runs `--strict` after every rollout can no longer ship a production without an enforced external anchor. Documented in `docs/en/operations.md`, the integration checklist and the README.

### Release engineering
- **Release gates are the CI gates.** The quality gates moved into the reusable workflow `.github/workflows/gates.yml` (audit/Pint/PHPStan, the PHP × Laravel × database matrix with lowest and highest dependencies and the 80 % coverage floor, the database-version matrix, the mutation gate with report artifact). `ci.yml` calls it on every push and pull request and keeps only the `experimental` matrix; `release.yml` calls it after the tag signature has been verified. A tag can no longer be released from a commit that would not pass CI, whatever `main` looked like when it was pushed; a release therefore takes as long as a CI run (about 50 minutes on the 2-vCPU runners of a private repository) — the previous release job re-ran audit, Pint, PHPStan and the tests on SQLite only.
- `timeout-minutes` on every job (mutation 120, the rest 10–30), `concurrency` on CI so a newer push to the same branch supersedes a running one (releases are never cancelled), and `.github/dependabot.yml` for the GitHub Actions pins (SHA and version comment together) and the four `composer.json` files (weekly; minor and patch bumps grouped, majors on their own) — the dependency watch `docs/release.md` had promised.

## 1.0.0-alpha.2 – 2026-09-25

Fixes for the findings of the security review of alpha.1 (all four
P0 items and the P1 items that did not need a schema change).

### security-tenant
- **Ownership is now checked on update, not only on delete.** A model loaded in one tenant context and saved, updated, incremented, touched or restored in another throws `TenantMismatch` (`TenantContextMissing` without a context). The check reads the original attributes, and every model `UPDATE`/`DELETE` is additionally constrained to the tenant at SQL level, so `saveQuietly()`/`withoutEvents()` cannot reach another tenant's row either.
- **Tenant middleware runs before route model binding.** `ResolveTenant`, `EnsureTenantMember` and `EnsureTokenTenant` are inserted into the middleware priority list right before `SubstituteBindings`; implicit binding of tenant-owned models inside the `web`/`api` groups now yields 404/403 instead of a `TenantContextMissing` 500.
- `TenantMismatch::onWrite()` replaces `onDelete()`; `TenantContextMissing::forWrite()` added.

### security-audit
- **No more InnoDB deadlocks on the first events of a chain.** The head row is provisioned in an auto-commit statement before the write transaction; `FOR UPDATE` only ever targets an existing row. Concurrency errors are retried with jitter (`audit.write.attempts`, default 5) when the writer owns the transaction and propagate to the caller's transaction otherwise. `Audit::prepareChain($tenantId)` provisions a chain up front.
- **`Audit::transaction($fn, attempts: 10)`** wraps a business transaction that contains audit writes and retries it with jittered back-off on concurrency errors (InnoDB deadlocks, PostgreSQL serialization failures, MariaDB ≥ 11.6 snapshot-isolation error 1020 "Record has changed since last read"). Found by the Docker concurrency run on MariaDB 11: with plain `DB::transaction(attempts: 5)` five of six parallel writers gave up.
- **Oversized secrets are redacted.** Values longer than 8 KiB are scanned in overlapping windows (JWT/bearer prefixes, PEM keys, cloud tokens anywhere in the value); values beyond 1 MiB are redacted outright. Previously such values skipped detection and were stored as a 1024-character plain-text prefix.
- **Tenant-less security events are never dropped.** `TenantScopeBypassed` outside a tenant context and denials for unknown tenants are recorded on the `global` chain regardless of `audit.tenant_policy`. `Audit::action(...)->global()` and `AuditEntry(global: true)` do the same for application events.
- Documentation: hashed columns stated precisely (`recorded_at` is not covered), database grants include `UPDATE` on `audit_chain_heads`, separate-connection atomicity caveat, `log` anchor store is write-only.

### Operations and defence in depth (review follow-up, "8.3 → 9")
- **`security:doctor`** (`--json`, `--strict`, `--no-verify`): environment, `APP_KEY`, signing key, database driver, append-only configuration and installed triggers, anchor stores, separate connection, anchor freshness per chain, last intact full verification per chain, live tail verification, tenant middleware priority, tenant cache store. Runs are recorded in the new `audit_verification_runs` table (also by `audit:verify`).
- **Production fail-fast**: in `APP_ENV=production` the audit provider throws `InsecureConfiguration` without a signing key, on SQLite, with append-only enforcement disabled or without a readable anchor store (`AUDIT_FAIL_FAST=false` to override deliberately).
- **Composite foreign keys**: `$table->tenantId()` now adds `UNIQUE(tenant_id, id)`; new `$table->tenantForeignId()` / `tenantForeignUuid()` / `tenantForeignUlid()` create `(tenant_id, column) → parent(tenant_id, id)` foreign keys, so the database itself rejects cross-tenant relations (raw SQL included).
- Tests for `SessionTenant` (switch, denial reasons, session resolver), `TenantSwitched` audit events, `LogAnchorStore`, a separate audit connection (`AUDIT_DB_CONNECTION`) including the lost atomicity, the doctor and the guard.
- `composer audit` in `bin/check` and CI. Documentation: `Audit::transaction()` is the primary recommendation everywhere; its closure may run more than once, so side effects stay outside.

### Second review round – release and proof
- **Mutation gate reproducible.** `bin/mutate` enabled pcov only for its own PHP process; Pest's `--parallel` workers ran with the Docker image's `pcov.enabled=0`, saw no coverage and reported every mutant as "uncovered" (score 0 %). The script now passes the coverage settings through the environment (`PHP_INI_SCAN_DIR`, `XDEBUG_MODE`), verifies the driver in a child process before mutating and fails fast with an explanation otherwise; `MUTATE_PATHS` and `MUTATE_PARALLEL` for partial and single-process runs. CI uploads the full report as an artifact.
- **`AUDIT_REQUIRE_EXTERNAL_ANCHOR`** (`audit.production.require_external_anchor`, default off): the production guard then demands a readable anchor store outside the database, validates that it can be instantiated (disk exists, class implements `AnchorStore`), and `security:doctor` reports database-only anchoring as FAIL instead of WARN.
- **Support matrix made explicit.** Hard CI gates: PHP 8.3/8.4 × Laravel 12 × four databases (+ lowest deps, database versions). PHP 8.5 and Laravel 13 moved to a clearly named `experimental` job that may fail; README, `docs/release.md` and `docs/operations.md` say so.
- **Release process.** `docs/release.md` (signed tags, versioning, upgrade/rollback, supply-chain rules), `.github/workflows/release.yml` (quality gates on the tag, `git archive` source tarball, SPDX + CycloneDX SBOM of the runtime tree, SLSA build provenance attestation, GitHub release with the CHANGELOG section as notes). All GitHub Actions pinned to commit SHAs.
- **Third review round:** the release workflow now verifies the tag cryptographically before anything else — annotated tag, `git verify-tag` against a trust root committed to the repository (`.github/allowed_signers` for SSH keys, `.github/release-keys.gpg` for OpenPGP), fail-closed when no key is committed (`gh release create --verify-tag` only checks that the tag exists). The `NullAnchorStore` (and any store derived from the database, log or null store) no longer counts as readable or external, so it cannot satisfy `AUDIT_REQUIRE_EXTERNAL_ANCHOR`; with that profile on, `security:doctor` probes the external store instances themselves and judges anchor freshness by what *they* hold, not by the database copy — a custom store that silently drops anchors is reported within one anchoring interval.
- **First CI run on GitHub (private repository).** The `tests` and `experimental` jobs failed in their install step: `composer show` takes one package, not three (the version print-out now loops). The `databases` job found a real defect that Docker had not: the optional tenant-bound fixture relation used `nullOnDelete()` on a composite key, which MySQL 8.0 and MariaDB refuse to create (errno 150, "Foreign key constraint is incorrectly formed") while SQLite accepts it silently — PostgreSQL would have accepted the constraint and refused the parent delete instead. `tenantForeignId()`/`tenantForeignUuid()`/`tenantForeignUlid()` now return a `TenantForeignKeyDefinition` that throws a `LogicException` on `SET NULL`/`SET DEFAULT` for `ON DELETE` and `ON UPDATE` at migration authoring time, on every driver; the fixture cascades. Reproduced and re-verified outside Docker on MariaDB 10.11, MySQL 8.0 and PostgreSQL 16 with the CI credentials (320 tests green each), line coverage 95.7 % under PHP 8.3 (CI gate `--min=80`). The release workflow skips the SLSA attestation unless the repository is public — GitHub issues attestations for private repositories on GitHub Enterprise Cloud only — and says so in the release notes; `docs/release.md` documents the private-repository chain of custody. The Laravel 13 rows of `experimental` fail as designed: `pestphp/pest-plugin-laravel ^3` does not allow `laravel/framework ^13` yet.

### Compatibility matrix and adversarial testing (review follow-up, "8.3 → 9")
- CI: PHP 8.3/8.4/8.5 × Laravel 12/13 × sqlite/pgsql/mysql/mariadb (highest deps), lowest deps on every database, database versions PostgreSQL 14/17, MySQL 8.0, MariaDB 10.11/11.4, and a mutation-testing job (see the second review round above for the final shape of the matrix).
- Docker: `PHP_VERSION` build argument (8.3 default), `matrix` mode, `DEPS=lowest` / `LARAVEL=13` for `install`.
- `bin/mutate` / `mutate` mode: Pest mutation testing on hashing, sanitising, signing, verification, writing, doctor, identifiers and tenant isolation. First run: 67 % of 1370 mutants killed; the survivors drove the `VerifierEdgeCasesTest`, `WriterEdgeCasesTest`, `DoctorEdgeCasesTest`, `TenantGuardEdgeCasesTest`, `SanitizerBoundariesTest` and `RequestContextResolverTest` suites (incremental verification and violation details, anchor signatures, head bookkeeping, explicit request context and its bounds, the doctor's thresholds, increments/upserts/multi-row inserts against the tenant column, mass-assignment opt-in, custom tenant columns, locator cache invalidation on rename, exact sanitiser and entry limits, canonical JSON) and the score now stands at about 75 % (2603 mutants, Docker run 75.1 %) with `--min=70` as the CI floor. The remaining "uncovered" lines were reviewed one by one: apart from declarations (constants, `$fillable`, pattern tables) they were defensive branches that `DefensiveBranchesTest` (audit and tenant) now exercises — empty-chain anchoring, composite-store fallback, foreign files in the anchor directory, unknown hash versions, self-describing actors, an unreachable audit connection in the doctor, membership helpers on unsaved users, blank actor ids, token-less users, custom builders with and without the guard, optional tenant-bound foreign keys, empty inserts. `SecretDetector::kinds()` lists every secret kind, and a test detects each of them (Slack and Google keys had patterns but no test). `docs/operations.md` explains which surviving mutants are accepted (defence in depth, timing, diagnostics).
- Found by the Docker matrix: on PostgreSQL a blanked `audit_chain_heads.last_hash` (`char(64)`) came back space-padded and was treated as a real predecessor hash by the writer and the verifier — both now trim it; MySQL's JSON type reorders object keys, so `AuditEvent::$metadata` now always reads back in canonical key order (`CanonicalJsonCast`). Neither affected hashes or verification of correctly written chains.
- Found on the way: `CanonicalJson` formatted `DateTimeInterface` values with a literal `Z` without converting to UTC (only reachable for dates that bypass the sanitiser; hashes of stored events are unaffected because timestamps are hashed as integer microseconds); `audit_events.occurred_at`/`recorded_at`, `audit_chain_heads.updated_at` and `audit_anchors.anchored_at` were written with whole seconds although the columns carry microseconds. All four now store UTC with microsecond precision.
- `RandomisedInvariantsTest`: property-style tests for canonical JSON, event hashing, public/global ids, tenant ids and the sanitiser (seeded, replayable).
- Opt-in load test (`--group=load`, `AUDIT_LOAD_WRITERS`): dozens of forked writers on two chains, mixed with business transactions.

### Tooling
- `start-security-framework.sh`: one Docker-only entry point (Docker check, databases with health checks, image build, Composer install on demand, selfcheck + Pint + PHPStan + test matrix, `concurrency`, `shell`, `down`). `bin/test` now runs every database and prints a per-database summary instead of stopping at the first failure.

## 1.0.0-alpha.1 – not released (superseded by alpha.2 before any tag)

First cut of the rebuilt framework.

### security-tenant
- Fail-closed `BelongsToTenant`: throws `TenantContextMissing` without a context, blocks tenant column changes, mass assignment and foreign deletes.
- `Tenancy::run()` / `Tenancy::withoutTenant(reason)` with events.
- Resolver chain (header, route, session, subdomain), locator with cache and status, strict identifier parsing.
- Memberships with status, expiry, hierarchical roles, `tenant.role` middleware, tenant-bound Sanctum tokens.
- Queue propagation via payload, `TenantAware` jobs, `tenant:run` command, request/Octane cleanup.

### security-audit
- Hash version 2: domain-separated canonical JSON over the complete record.
- Per-chain head rows with `FOR UPDATE` serialisation and sequence numbers.
- Append-only triggers for PostgreSQL, MySQL, MariaDB and SQLite; unsupported drivers abort the migration.
- HMAC-SHA256 signatures with a keyring outside the database; `audit:key:generate`.
- Anchor stores (database, filesystem, log), `audit:anchor`, `audit:verify` with chunked verification and eleven violation types.
- Sanitizer with token matching, secret-shape detection, keyed pseudonymisation and visible markers.
- Automatic recording of tenant security events.

### security-addressing
- Strict `PublicId` and `GlobalObjectId` value objects (lowercase, canonical or invalid).
- Crockford base32 bodies with 80 bits of entropy by default.
- `HasPublicId` with immutability, mass-assignment guard and safe route binding; `$table->publicId()`.
